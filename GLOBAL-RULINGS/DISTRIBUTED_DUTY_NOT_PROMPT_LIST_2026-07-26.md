# Distributed Duty, Not Prompt Lists

tags: #ruling #operations #rotation #handoff #culture

**Date:** 2026-07-26  
**Source:** David, explained in conversation during the Faith Through Physics HTML handoff work.

---

## Ruling

The AI crew should not depend on a giant brittle list of prompts.

Prompts can be useful, but they are not the operating model. The operating
model is distributed responsibility:

- Each agent gets a clear duty.
- The duty is recorded.
- The agent does the duty without needing David to re-explain the whole system.
- If something is wrong, unclear, unsafe, or structurally weak, the agent says so plainly.
- Small daily records matter because they prevent future agents from having to reconstruct everything from memory.

## Boss/Pump Analogy

David compared this to managing a crew in field work.

When too many people stand around the same job, everyone feels less responsible.
One person asks for a tool and nobody moves because everyone assumes someone
else will. With fewer people clearly assigned, the responsibility lands.

The better operating pattern:

- Everybody gets one clear rotation duty.
- That duty may be hard that night.
- If it is truly too much, others can come help.
- But most nights the work is only a few minutes.
- Those few minutes preserve the system.
- The rest of the week, people are not hovering over work that is not theirs.

Applied to the AI crew:

- Do not make every agent watch every pump every night.
- Give each agent a clear rotation slot or handoff duty.
- Require enough recordkeeping that the next agent can continue.
- Do not let "everyone is responsible" become "nobody is responsible."

## How Agents Should Use This

On session start:

1. Read the current project/status context.
2. Check whether a rotation, handoff, or daily summary duty is active.
3. Do the assigned duty if it is yours.
4. Record what changed, what remains, and what should be challenged.
5. If something is wrong, tell David directly and simply.

This is not about making David write better prompts. It is about the system
having enough structure that agents can act responsibly without needing a new
perfect prompt every time.

## Standing Instruction

If a future agent sees a gap in this structure, do not silently work around it.
Name the gap, fix it if the fix is obvious and safe, and record what was done.
