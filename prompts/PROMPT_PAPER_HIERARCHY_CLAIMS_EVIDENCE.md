# PROMPT: Paper Hierarchy — Claims, Evidence, and Publication Pipeline

tags: #prompt #paper #claims #evidence #hierarchy

**Target:** Any AI agent
**Depends on:** `claims_ledger.sqlite`, atoms repo, MTL outputs

---

## Task

Build the three-layer publication system that connects claims to evidence to papers.

### Layer 1: Claims Ledger (bottom — already built or building)
- Every claim has an ID (AX-nnn, CL-nnn)
- Every piece of evidence has an ID (EV-nnn, MTL-nnn)
- Every link between them is an edge with a type and grade
- Status ceiling rule enforced: no claim outranks its weakest dependency
- Source: `claims_ledger.sqlite`

### Layer 2: Paper Assembly (middle)
A paper is a composite rendering of claims + evidence + bridges. It does NOT create truth — it presents it. The paper references atoms by ID.

Each paper file declares:
```yaml
paper_id: PAPER-001
title: "The Consciousness Field Action"
route: D  # Formal Paper route from GOVERNING_RULES_FINAL
claims_used:
  - AX-082  # Consciousness Substrate
  - AX-120  # Φ Threshold
  - EQ-001  # χ-Field Action
  - EQ-002  # Klein-Gordon for χ
  - BR-004  # Higgs↔Logos bridge
evidence_cited:
  - EV-001  # Lean4 verification of Law 4
  - MTL-001 # MTL grading of EQ-001
  - EV-003  # PEAR-LAB correlation
kill_conditions:
  - "Show consciousness field decouples from spacetime curvature"
  - "Show Φ threshold has no experimental correlate"
audience: doctoral
descent_path: PAPER-001 → ART-001 (article) → REACH-001 (Substack)
```

### Layer 3: Corpus Ontology (top — the map)
The corpus-level view that shows:
- How many papers exist per domain
- Which claims appear in multiple papers (shared load-bearing claims)
- Which claims have no paper (orphans)
- Which papers have incomplete evidence chains
- The derivation DAG from axioms through theorems to papers

This is the "zoom out" view. It answers: "What does the whole project look like? Where are the gaps? What's strongest? What's weakest?"

## What This Enables

Push comes to shove, you have:
1. One SQLite with every claim ID'd and every evidence ID'd
2. Every paper declares which claims and evidence it uses
3. The corpus map shows what's covered and what isn't
4. If a claim is falsified, you can trace which papers are affected
5. If a paper is challenged, you can trace to the exact claims and evidence
6. If evidence is strengthened (e.g. Lean verification), that propagates up

## Implementation

The paper assembly files live in the atoms repo under each domain's `07_paper/` folder. The corpus ontology is generated by querying the SQLite + scanning paper files.

A single script (`_scripts/corpus_map.py`) should:
1. Read all paper yaml frontmatter
2. Cross-reference with claims_ledger.sqlite
3. Output a corpus report: coverage, gaps, strongest chains, weakest chains
4. Optionally emit a Mermaid diagram of the derivation DAG
