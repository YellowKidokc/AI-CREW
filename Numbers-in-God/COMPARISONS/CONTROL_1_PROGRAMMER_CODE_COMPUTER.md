# CONTROL 1 - Programmer -> Code -> Computer

Codex negative-control ablation suite  
Date: 2026-08-04

## Control Purpose

This is the hardest ordinary control because it mimics the target grammar:

```text
author/source -> formal language -> executing physical system
```

If this control scores too high, the proof program cannot treat "source -> formal mediator -> realized system" as unique to God/Math/Physics.

## Scoring Rule

0 = no match  
1 = weak analogy  
2 = bridge analogy  
3 = ambiguous / partial structural match  
4 = strong structural match  
5 = near identity inside the control triad

Criteria considered for every cluster:

- identical meaning across all three domains;
- required for the domain to function;
- same structure and same violation consequences;
- bidirectional readability;
- boundary pattern preservation: source -> formal mediator -> realized domain -> feedback/recognition.

## Boundary Pattern Audit

The P/L/N/F-style boundary pattern holds locally:

```text
programmer source -> code language -> computer execution -> output feedback
```

But it is bounded and artifact-level. It does not ground truth, being, mathematics, physics, or universal knowability. This is a strong control for generic authorship patterns and a weak control for ultimate metaphysics.

## Discrimination Finding

This control breaks at Modal, Ontological, Epistemic, and Scale.

It shows that Logical, Structural, and Evaluative clusters are not discriminating by themselves. Many authored formal systems pass them.
